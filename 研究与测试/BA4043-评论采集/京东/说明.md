# 京东试采 · 买家晒单

2026 年 11 月 24 日取得 5 条公开买家晒单。采集时刻为北京时间 21:38:50，二次核对时刻为 21:38:52。五条记录来自不同商品，其中第 4 条明确谈及送礼，另四条提供规格、品质或收货体验背景。没有对应长健农业的订单或消费者身份资料。

## 来源和取样顺序

计划中的[商品集合](https://www.jd.com/hprm/1221846fd01171942c7be.html)没有直接展示可采的晒单文本，改用京东[热门点评晒单](https://www.jd.com/phb/key_12218469e4083a9593e75.html)。按本次 Python 访问时页面自上而下的商品顺序，排除第 1 位的冻荔枝和第 2、3 位的红毛丹后，依次收录第 4–8 位。

| 榜单位置 | 商品和入选依据 |
| --- | --- |
| 4 | 仙进奉荔枝。评价涉及盒子大小、包装和配送。 |
| 5 | 玉荷包荔枝。虽然评价简短，买家具体描述了分量和个头。 |
| 6 | 妃子笑荔枝。买家提到运输中的果损、防护及给家人食用。 |
| 7 | 妃子笑荔枝。买家提到包装防护、实际等待时间，以及送人的适用性。 |
| 8 | 白糖罂荔枝。买家提到冰袋、价格与品质比较，以及回购理由。 |

榜单是平台筛选后的展示位置，页面和次序会更新。只有一个条目明确提到送人，不能用这五条推论高端送礼者的需求比例。

## 核对与复跑

- `raw.json` 保存京东原生榜单两次访问的原始晒单 HTML 片段、商品条目及带时区的时间戳。每一行按原生标识、原文、商品名和详情链接比对，两次均一致才进入 `pilot.csv`。
- CSV 中的 `source_url` 指向实际展示原文的京东页面并附加文本定位；`listing_position` 提供人工查找位置。`detail_url` 是京东在该原文上提供的晒单详情入口。探查时首个详情入口返回“活动太火爆，请稍微再试”；五条入样的复核均使用可正常读取原文的京东榜单。数据类型为买家晒单；未将商品介绍、问答或晒单下的回复混入。
- Python 3.12 依赖 `requests` 和 `beautifulsoup4`。在本目录执行以下任一命令，输出到新的子目录。在线运行仍依赖榜单继续展示本次审阅的原生标识；页面更新时，按实际匹配数量报告。

```powershell
py -3.12 collect_jd.py --out ./新访次
py -3.12 collect_jd.py --replay ./raw.json --out ./复核结果
```

## 正式样本

`full.csv` 包含原 5 条及 15 条新增记录。12 条评论针对鲜荔枝（JD-01 至 JD-11、JD-20）；另外 8 条来自其他节日鲜果或礼盒，含混合果篮、苹果、释迦、梨、猕猴桃和车厘子。JD-12 写明准备提果篮去老朋友家；JD-04 表示这款荔枝适合送人。两条都没有证实收礼人已实际收到产品。商品名称中出现“送礼”不能单独作为买家送礼经历的证据。

按来源序号、再按其页面位置读取公开晒单。平台页面顺序会更新，搜索索引有时与当次页面完全不同。以下为新增样本的入选位置；`full_raw` 保留来源各两次访问的公开条目片段和北京时间。优先选择鲜荔枝的具体体验；其他鲜果只收录与节庆礼赠、礼盒或对本题有明确借鉴价值的包装、损伤、规格和产地信任经历。

| 来源号 | 新收录的页面位置 | 筛选情况 |
| --- | --- | --- |
| 01 | 10 | 续接试采。第 9 位是无关引用。 |
| 02 | 2、8、9 | 新增无坏果、冷链价格和可观察鲜度体验。其余含空白默认评价、跨页重复、冻荔枝、模板或反复相同的措辞。 |
| 03 | 2、3 | 两条黑叶鲜荔枝体验。首条为冻果。 |
| 04 | 1 | 带水果的礼盒有明确探亲访友情境。其余为空盒。 |
| 05 | 无 | 含冷冻榴莲或主要说味道，未提供额外礼赠决策线索。 |
| 06 | 1、3、6、7、10 | 仅保留具体节日鲜果比较；包括关于产地标示、规格与果品状况的负面意见。 |
| 07 | 无 | 主要为无关的保健产品等；普通苹果评价未补入。 |
| 21 | 1 | 彩箱猕猴桃礼盒的具体到货、后熟和家人食用体验。 |
| 22 | 6 | 车厘子礼盒晒单记录挤压；其余主要为普通箱果、泛评或重复。 |
| 23 | 9 | 妃子笑的家庭回购理由；大部分其他荔枝晒单已出现。 |
| 24 | 无 | 实际出现果木炭、酒、罐头等，未因榜单标题含“荔枝”而入选。 |

评论原文由 Python 从 HTML 获取。筛选理由、语境和主题由 AI 辅助逐条审读整理，未标作组员复核。每条新增记录的类别与入选依据保存在 `正式编码.json`，按平台原始 ID 关联；原文和商品名仍取自两次公开页面。准入要求为原生标识、文字、商品与详情链接均吻合。对原始 ID 和压缩空白后的文本双重去重。正式样本为平台挑选展示的晒单，不能据其外推买家总体或识别收入水平。

在本目录执行以下命令，离线重建完整 CSV；`full_jd.py` 复用试采解析器和保留的 5 条试采数据。要回放试采，先用上一节独立命令重建并比对原 `pilot.csv`。

```powershell
py -3.12 -B full_jd.py build ./full_raw ./full-replayed.csv
```

如需新访次，以文件名前缀记录来源顺序；每个文件名中的 `key_` 值就是 URL 的公开榜单编号。例如以下命令会对同一原站页面发起两次独立 GET，并存入新目录。榜单变动会导致复采时相同原 ID 减少，这是正常的时间差异。

```powershell
py -3.12 -B full_jd.py capture 12218469e4083a9593e75 ./新访次原始/01-12218469e4083a9593e75.json
```
