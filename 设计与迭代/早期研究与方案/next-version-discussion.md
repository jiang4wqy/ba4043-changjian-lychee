## 前端建议

候选方式包括分幕单页、多页导航、滚动吸附分屏。用户已选择分幕单页：保持现有内容的连续性，由点击驱动切换，并允许目录跳转。多页会增加页面文件和跳转；滚动吸附仍主要依赖滚动，不是本次选择。

| 幕 | 内容 | 建议主入口 |
| --- | --- | --- |
| 01 品牌 | 开场之后的品牌、品名与主图 | 认识荔枝；也可直接查看礼盒 |
| 02 荔枝 | 品种背景、果肉实拍与供应说明 | 查看礼盒 |
| 03 礼盒 | 外观、盒内与细节展示，礼赠场景 | 走近果园；随时咨询规格 |
| 04 长健与果园 | 果园、公司招牌与其他水果摘要 | 购买前说明 |
| 05 购买前说明 | 供应、规格、配送与保存问题 | 咨询产品 |
| 06 咨询 | 咨询主题、字段与反馈 | 提交咨询；返回其他幕查看信息 |

建议交互规则：

- 桌面突出一幕内容，显示当前位置（如 03 / 06）、上一幕与下一幕。
- 主目录与咨询入口持续可达；不强制读完前面的幕才能咨询。
- 桌面采用统一的短转场，可借鉴帘幕／分片揭示；仍以实拍与文字为中心。照片切换、FAQ 和咨询验证保留。
- 手机上内容超出屏幕时可在当前幕内正常滚动，不截断表单或缩小正文。
- 各幕使用明确的 URL 片段，浏览器返回键和直接链接可定位对应内容。
- 键盘可操作；切换后将焦点移到对应标题。减少动态效果时直接切换；JavaScript 不可用时仍可浏览正文。

参考：Codrops, *Fullscreen Scrolling Slideshow*, 17 August 2022，https://tympanus.net/codrops/2022/08/17/fullscreen-scrolling-slideshow/ 。参考其分屏内容视图与直接目录的组织方式，计划改成点击驱动；尚未复制代码或接入其 GSAP 依赖。具体动画代码选定后再核对许可并记录修改。

## 后端建议，尚待定案

最小范围是实际接收咨询，而后小组能查看保存结果：

1. 浏览器检查必填项，发送称呼、联系方式、主题及问题。
2. Flask 在服务器上再次验证输入；错误时返回明确字段信息。
3. 校验通过后写入数据库，返回成功状态及咨询编号；保存失败时不显示成功。
4. 小组经登录保护的页面查看记录。咨询记录不通过公开列表展示。

此功能是咨询收集，不构成订单、付款或商家承诺。当前工作名称、供应、规格、价格与实际联系渠道仍需确认。

建议以 Flask 和 SQLite 起步：适合小规模课程演示，便于解释实际请求、数据库记录和反馈。SQLite 放在服务器持久化磁盘；如果所选托管方式没有持久化磁盘，需选持久化数据库，避免重启或重新部署丢失记录。部署方式确认后再确定最终数据库。

从演示改为实际保存时，页面说明必须同步变更，明确谁接收信息、保存用途以及是否为课程项目；不能继续展示“不提交、不保存”。在没有商家承接时，成功反馈写为课程网站收到咨询，不冒充企业已经联系或接受订单。

依据：Flask 官方数据库教程，https://flask.palletsprojects.com/en/stable/tutorial/database/ 。上述功能范围是本项目建议，不是官方教程已有的项目功能。

## 部署与课程证据

服务器选型稍后根据现有账号／服务器、课程演示时间与预算确定。可以使用云服务器或支持 Python 的托管服务。将页面与接口放在同一网站地址，提供可访问 HTTPS 网址；实际后端使用生产服务器运行。Flask 官方说明：https://flask.palletsprojects.com/en/stable/deploying/ 。目前不购买服务器、不创建外部服务、不发布网站。

验收计划：

- 分幕版：每幕可前进／返回、目录可直达、链接和浏览器返回行为正确；桌面与手机内容完整、控件可达；主咨询任务仍能完成。
- 后端版：无效请求被服务器拒绝；有效请求实际落库且编号对应；小组登录后能找到该记录；失败、重复点击有明确反馈，数据库在重启后仍存在。
- 上线版：从另一台设备打开公开网址完成咨询，再在受保护页面核对结果；按实际结果保留截图。
- 英文报告：结合分幕设计、真实接口、数据库及部署说明撰写，与最终源码包相符。补充 Python 依赖和启动说明。
- 真实访谈若要争取：短访谈记录受访者实际问题、日期与方法，并连接到页面修改；二手资料研究保留，不冒充访谈。

建议顺序：前端分幕交互 → 本地真实咨询后端 → 服务器部署 → 实际设备检查与英文报告。后续预算、服务器环境与访谈安排尚未确定。
