摘要

本项目以广州市长健农业发展有限公司的荔枝及礼盒参考资料为基础，制作面向亲友送礼与家庭分享场景的营销网站。网站将品种背景、礼盒实拍、来源介绍、购买前说明和咨询入口组织为六个章节，采用浅绿色、宋体标题与圆窗转场表达清雅国风。访客可以查看产品信息、选择送礼场景并提交咨询；咨询经后端验证后保存，小组可登录后台查看。网站已完成 HTTPS 部署和自动化检查。本报告说明调研如何影响内容与布局，结合源码解释功能，并记录已经完成与仍需补充的验证。

1 项目背景与目标受众

1.1 真实项目与当前状态

项目参考对象是广州市长健农业发展有限公司。提供的需求书介绍了企业及水果产品，素材中包含可辨认公司名称的招牌、荔枝、果肉、包装和果园环境照片。它们为选择真实农业项目提供依据。[1] 本次制作成果是围绕该项目的课程营销原型，已上线；企业最新经营情况、实际在售品种、礼盒净重、价格、库存以及正式销售链接仍需进一步核实。

网站暂以“仙进奉荔枝礼盒”为工作主题。农业科研机构的品种资料支持一般品种介绍，但不能证明素材中的每个果实属于该品种，也不能证明企业当前有货。[5] 因此，页面将未知规格和供应条件写成购买前需要确认的问题，不填入假价格、销量或配送承诺。网站的咨询记录由课程小组查看，不代表企业已接单。

1.2 受众与预期行动

主要受众是想给亲友送水果礼盒的个人消费者，次要受众是希望与家人分享时令鲜果的人。送礼者可能关注外观、分量、品种和到货安排；家庭分享者可能更关注数量、新鲜度与保存。这些是从资料和商品表达推导的任务需求，尚未通过消费者访谈验证，不使用虚构年龄、收入或偏好比例。

希望访客完成的主要行动是：查看荔枝与礼盒实拍，选择适合自己的使用场景，了解需要确认的规格与寄送问题，最后提交咨询。咨询表单询问称呼、主题、联系方式和可选补充问题，并要求同意保存信息。成功后显示编号，让访客知道系统确实收到记录。

2 调研方法与发现

2.1 调研方法

2026 年 10 月 11—12 日的调研采用三种方式：阅读已提供的项目资料，观察原素材中的产品与包装，以及检索公开报道、官方品种资料和同类商品页面。原素材包共 28 个文件，网页选用其中 8 张照片的压缩副本。没有开展问卷、潜在用户访谈或消费者偏好统计。

研究问题是：真实荔枝产品如何围绕礼赠形成主线，以及访客需要哪些信息才能进入有意义的咨询。公开信息提供内容线索；页面设计是对这些线索的解释，不把行业报道当成对本企业的用户调查。

3.2 清雅国风与阅读层级

视觉采用浅绿底色、深绿正文、宋体大标题、少量红色印章和原创枝叶 SVG。绿色与水果、果园主题相配，圆窗呼应传统园林的取景方式。首屏“一盒荔香，赠予所念”用于传达礼赠情绪，旁边保留产品名称与明确的咨询入口。这个视觉方向来自项目讨论和定位，不声称它由调查百分比决定。

大标题负责传达主题，小字说明来源与限制，规格和购买问题放在对齐的信息区。较长正文使用段落、清单及可展开 FAQ，便于手机阅读。附图 1 展示首屏，附图 2 展示场景选择；它们说明诗意表达如何与实际任务结合。

3.3 浏览与互动

网站采用点击目录切换章节的方式，每次显示一幕。圆窗转场延续照片与文字的关系，而底部目录保持可见，访客仍能直达任何章节。每幕内部允许正常滚动，确保长内容和表单反馈可到达。章节地址如 #gift 和 #enquiry 支持直接进入，浏览器返回、前进与刷新也保持对应内容。

例如，访客进入“荔礼”，选择“致谢相赠”，再点击咨询入口，表单会带入礼盒主题与对应问题草稿。已有输入正文会保留。相册切换、照片放大、FAQ 展开和表单校验都提供可见响应；减少动态效果偏好会关闭自动开场并直接切换章节。

4.3 咨询保存与错误反馈

前端先检查称呼、主题、手机或邮箱格式、补充内容长度和保存同意；连接后端后，再以 JSON POST 到 /api/enquiries，并附带 CSRF 令牌。服务端再次检查数据，避免绕过页面验证的非法输入被保存。SQLite 使用参数占位符插入值，提交成功才返回编号。以下是 app.py 的实际摘录：

app.py 第 153—163 行

try:    with sqlite3.connect(app.config["DATABASE"], timeout=5) as db:        cursor = db.execute(            "INSERT INTO enquiries (customer_name, topic, contact_method, contact, message, consent) VALUES (?, ?, ?, ?, ?, 1)",            tuple(values[name] for name in ("customer_name", "topic", "contact_method", "contact", "message")),        )        record_id = cursor.lastrowidexcept sqlite3.Error:    app.logger.error("Enquiry database write failed; no success response issued.")    return jsonify(message="咨询暂未保存，请稍后再试。"), 503return jsonify(reference=f"CJ-{record_id:06d}", message="咨询已保存，课程项目小组可查看这条记录。"), 201

返回 201 表示记录已经写入，返回 422 提示字段有误，数据库写入失败返回 503。前端在等待时禁用重复提交，成功显示编号；失败保留内容，不显示“已保存”。联网、服务器失败与写入失败的检查结果见第 6 节。附图 3—5 展示校验与真实保存反馈。

直接打开 index.html 时，表单旁明确标注只演示校验，不发送或保存信息。HTTP 后端连接失败时提交禁用，并提供重试。这保证演示状态和真实保存状态可以区分。

4.4 管理页与依赖

/admin 要求独立管理密码；未登录者转到登录页。密码由 Werkzeug 哈希处理，管理页面由 Jinja 自动转义用户文本。[14][15] 记录按新到旧排列，每页 50 条，时间显示为北京时间。提交、登录及退出验证 CSRF 令牌；后台与 API 响应不缓存。前端静态路由限定公开文件，数据库与密钥不能通过网页下载。

运行版本为 Flask 3.1.3、Waitress 3.0.2、Werkzeug 3.1.9、Jinja2 3.1.6。其余锁定依赖为 MarkupSafe 3.0.4、itsdangerous 2.2.0、Click 8.1.8、Blinker 1.9.0、colorama 0.4.6、importlib metadata 8.7.1 和 zipp 3.23.1。原始许可证保留在随包 wheels 中。

pytest 与 Playwright 用于测试，Pillow 用于图像副本和排版准备；它们不是网站运行依赖。制作过程使用了 AI 辅助整理资料、编写与检查代码，正式报告应结合成员实际复核和修改记录说明工作。
