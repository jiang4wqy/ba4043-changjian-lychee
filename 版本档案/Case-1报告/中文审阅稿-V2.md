1 项目背景

1.1 公司与产品

我们选择广州市长健农业发展有限公司作为本次营销网站的项目对象。长健农业参与广州增城的荔枝种植与品牌推广。广州市农业农村局在 2025 年 2 月发布的公示中，记录了公司相关负责人建立 180 亩荔枝种植基地、创立“增仙荔”品牌的事迹。[1] 广州市人大网站同年 6 月转载的报道介绍，公司通过与合作社及农户协作开展荔枝种植和推广。[2] 在 2026 年 6 月发布的农业补贴公示中，公司也以荔枝种植主体列出。[3]

项目资料包含企业介绍、公司招牌、荔枝挂果、果肉、礼盒和果园照片。这些素材让我们能够从企业、产品和包装三个方面介绍长健农业。[4] 本次网站集中展示仙进奉荔枝礼盒，围绕亲友送礼和家庭分享组织内容。

1.2 选题与网站任务

选择荔枝礼盒，是因为它有明确的使用场景，也有适合网页展示的实物素材。赠送水果时，购买者除了关心好不好吃，还需要了解包装是否合适、分量能否满足分享，以及寄送时间如何安排。荔枝又具有明显的季节性，因此品种与供应信息也会影响选择。

我们希望网站帮助访客逐步了解产品，再把自己的问题整理成咨询。网站的主要任务是展示荔枝和礼盒、说明购买前需要考虑的事项，并提供可填写、可保存的咨询入口。这样的目标让每个章节都有具体作用，也便于检查访客能否完成整个流程。

2 调研方法与发现

2.1 查阅了哪些资料

我们在 2026 年 10 月 11—12 日整理企业资料，观察产品照片，并查阅公开网页。调研重点放在三个问题上：长健农业具有什么产品背景，荔枝礼盒如何在市场上呈现，以及访客选择礼盒时需要了解哪些信息。

企业部分阅读了项目需求书、广州市农业农村局的公示和广州市人大网站的相关报道；产品部分查阅了广东省农业科学院的仙进奉品种介绍；市场部分阅读了羊城晚报和增城政府门户的荔枝报道；商品信息部分观察了京东“增城荔枝”聚合页面；保存与收货部分参考了重庆市市场监督管理局的消费提示。这次研究采用资料查阅和页面观察，记录的是各类信息如何被呈现，以及它们对本项目的启发。

我们同时查看了素材包中的 28 个文件，按荔枝、果肉、包装和环境分类。网页使用其中 8 张照片的压缩副本。外盒、内盒和包装细节能够相互补充，因此保留为礼盒相册；公司招牌和果园照片用于介绍企业与产品来源。

2.2 市场与商品信息

羊城晚报 2026 年 7 月 10 日的报道引用广东省监测数据：截至报道所述的 7 月 9 日，广东荔枝销售量约 120 万吨，销售金额超过 213 亿元。同一报道举出从化“流溪红”进入精品礼盒渠道的案例，6 粒装售价 299 元，18 粒装定价 498 元。[5] 这些数据提供了广东荔枝市场的背景，礼盒案例则让我们看到，包装和赠礼用途可以成为产品介绍的重点。

增城政府门户 2026 年 6 月的报道介绍了荔枝风味图和表达心意的礼盒。[6] 结合现有包装照片，我们决定把礼赠用途作为网站主线。首屏先呈现荔枝与心意，后续章节再解释品种、实物包装和选礼问题，使访客能从产品外观逐步进入具体选择。

商品页面提供了另一种启发。京东聚合页可见“白糖罂荔枝约 450g”这类标题，直接把品种和重量放在商品名称里。[7] 我们据此把规格、包装和数量问题放在礼盒介绍与购买清单中。访客看完图片后，能够继续找到与购买有关的信息，而不会停留在一句宣传语上。

广东省农业科学院的资料介绍了仙进奉的晚熟特征和果实外形。[8] 我们将这部分写成简短的品种说明，配合果肉照片阅读。重庆市市场监督管理局则提醒荔枝保鲜期短，应按需购买，剩余部分冷藏并尽快食用。[9] 因此，购买前说明同时包含收货时间、配送与保存，帮助送礼者提前考虑这些安排。

3 目标受众与访客行动

主要受众是准备给亲友送水果礼盒的个人消费者，次要受众是希望与家人分享鲜果的人。前者需要判断礼盒是否适合赠送，并安排数量和时间；后者更关心产品特点、分享分量和保存方式。我们的内容围绕这些任务展开。

网站希望访客完成的行动是提交产品咨询。一个典型流程是：从首页进入礼盒章节，查看包装照片，选择送礼场景，阅读相关说明，再填写联系方式和问题。提交的信息保存到项目后台，供小组查看和整理。表单成功后显示咨询编号，使访客得到明确反馈。

为了让不同访客都能找到入口，首页和目录提供直接咨询链接，礼盒、选礼清单和常见问题也连接到表单。熟悉产品的人可以直接咨询，第一次了解产品的人则可以先浏览详细内容。

4.2 视觉与文字

我们采用浅绿色背景、深绿色正文和宋体标题，使页面与水果、果园主题保持联系。少量红色印章和枝叶图案增加国风细节，圆窗则让荔枝照片形成清晰的视觉中心。首屏“一盒荔香，赠予所念”表达礼赠意味，旁边保留产品名称与行动入口，方便访客继续浏览。

诗意文字主要用于标题，品种、规格和流程说明使用直接的表达。这样既保留品牌氛围，也能让访客读懂实际信息。正文用段落和对齐的信息区组织，手机上改为单列；长答案放入可展开的常见问题，减少同一画面中的文字量。

4.3 导航与场景选择

页面采用分章浏览。点击目录后，圆窗转场带出下一章，底部目录仍然可见，当前章节也有标记。地址中的 #gift、#enquiry 等片段支持直接定位，浏览器返回、前进与刷新保持对应章节。

礼赠场景的作用是帮助访客准备咨询。例如选择“致谢相赠”后，页面会显示与该场景有关的说明，点击咨询入口会带入主题和问题草稿。如果访客已经填写正文，原有输入会保留。相册切换、照片放大和常见问题展开也都提供可见响应。

开场动画可以跳过或重播。页面响应减少动态效果的系统偏好，采用直接切换并关闭自动开场；不运行 JavaScript 时，六章内容仍可作为普通长页面阅读。

chapters.js 根据点击和地址选择章节，通过 hidden 属性显示对应 section，并更新当前目录与浏览器历史。下面的实际源码摘录展示了切换章节和重置阅读位置的逻辑：

chapters.js 第 71—73 行

chapters.forEach((section, i) => { section.hidden = i !== index; });activeChapter = index;chapterMain.scrollTop = 0;

CSS 在窄屏下将内容改为单列，底部目录改为三列两行。转场使用浏览器原生动画，快速点击时取消旧动画，避免多个画面同时停留。标题焦点随章节移动，开场、相册弹窗与目录也支持键盘操作。

5.3 咨询表单与数据库

表单检查称呼、主题、手机或邮箱格式、补充内容长度和保存同意。连接后端后，前端以 JSON 提交到 /api/enquiries，并附上用于会话验证的 CSRF 令牌。服务端再次检查字段，再通过参数化 SQL 写入 SQLite。以下为 app.py 的实际摘录：

app.py 第 153—163 行

try:    with sqlite3.connect(app.config["DATABASE"], timeout=5) as db:        cursor = db.execute(            "INSERT INTO enquiries (customer_name, topic, contact_method, contact, message, consent) VALUES (?, ?, ?, ?, ?, 1)",            tuple(values[name] for name in ("customer_name", "topic", "contact_method", "contact", "message")),        )        record_id = cursor.lastrowidexcept sqlite3.Error:    app.logger.error("Enquiry database write failed; no success response issued.")    return jsonify(message="咨询暂未保存，请稍后再试。"), 503return jsonify(reference=f"CJ-{record_id:06d}", message="咨询已保存，课程项目小组可查看这条记录。"), 201

成功响应为 HTTP 201，包含咨询编号；字段错误返回 422，数据库写入失败返回 503。前端提交期间禁用重复点击，保存成功后显示编号，失败时保留输入并显示错误。直接打开 index.html 时，表单旁说明仅演示输入检查，不提交或保存信息，符合本地演示的要求。

5.4 管理页与第三方工具

/admin 使用独立密码登录，未登录的访问转到登录页。密码由 Werkzeug 哈希处理，Jinja 自动转义用户输入，记录按新到旧排列，每页 50 条，时间显示为北京时间。[17][18] 登录、提交和退出验证 CSRF 令牌，管理及 API 响应不缓存，公开文件路由限定在网页资源范围内。

运行版本为 Flask 3.1.3、Waitress 3.0.2、Werkzeug 3.1.9 和 Jinja2 3.1.6。其余依赖包括 MarkupSafe 3.0.4、itsdangerous 2.2.0、Click 8.1.8、Blinker 1.9.0、colorama 0.4.6、importlib metadata 8.7.1 和 zipp 3.23.1，版本锁定于 requirements-lock.txt，原始许可证保留在 wheels 中。

pytest 和 Playwright 用于自动检查，Pillow 用于图像副本处理。项目制作也使用 AI 工具辅助资料整理与代码工作。

6.2 部署过程

网站于 2026 年 10 月 12 日部署到 Ubuntu 22.04 服务器，使用 Python 3.10.12 和独立虚拟环境。Waitress 监听 127.0.0.1:8051，Caddy 2.11.4 提供 HTTPS 反向代理与证书，systemd 管理应用进程并设置开机启动。[19] 数据库、管理密码哈希和会话密钥位于 /var/lib/changjian-agri，与代码版本目录分开。

上线后检查了 HTTPS 证书、网页资源、咨询提交和管理登录，再重启应用服务确认记录保留。16 个运行文件的 SHA-256 与交付源码一致，源码压缩包完整性检查通过。网站可通过本报告开头的完整网址访问。

6.3 本地运行

源码包包含网页、后端、依赖和 README。完整解压后，在 Windows 创建虚拟环境、安装锁定依赖并启动：

python -m venv .venv.venv/Scripts/python.exe -m pip install --no-index --find-links vendor/wheels -r requirements-lock.txt.venv/Scripts/python.exe app.py --setup.venv/Scripts/python.exe app.py

设置管理密码后，浏览器打开 http://127.0.0.1:5000/，管理页为 /admin。离线安装检查使用了 Windows Python 3.9.13 和 Ubuntu x64 Python 3.10.12；Linux 启动方法在 README 中说明。
